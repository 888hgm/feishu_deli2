# 关键节点完成汇总表 · v1.0.2

独立的飞书多维表格仪表盘插件。按“上市月份 × 产品公司”生成类似 Excel 的汇总表，每个节点展示计划有效数量、实际有效数量和状态完成率。与之前的多横轴柱状图插件分开使用。

**升级到 v1.0.2：** 本次调整完成率口径，排除计划、实际时间均无有效内容的“未完成”，保留列宽调整和低完成率标红。把新包内容更新到原“汇总表”仓库并在飞书更新发布即可，无需另建插件。旧字段映射、范围、列宽和标红设置会保留，无需额外开启新规则。

## 先上传 GitHub，再发布到飞书

1. 解压精简上传包。**上传解压后里面的文件和文件夹，不要只上传 ZIP，也不要再包一层文件夹。**
2. 在 GitHub 新建一个独立的公开仓库，例如 `feishu-milestone-table`。保留原柱状图仓库。
3. 使用仓库的 `Add file → Upload files`，把解压后的内容拖进去并提交。文件总数低于 100。
4. 打开仓库根目录，确认可以直接看到 `package.json`、`src`、`scripts` 和 `dist`；点开 `dist` 可以直接看到 `index.html`。
5. 在飞书多维表格开发者中心新建一个商品，商品类型选择“插件”，插件类型选择“仪表盘插件”。
6. “插件代码 Github 地址”填写 **GitHub 仓库地址**，形如 `https://github.com/你的用户名/feishu-milestone-table`。这里填写仓库地址，服务预览网址不能替代仓库地址。
7. 按页面要求填写基础信息，先选“本人可见”测试，再点击发布。包中已经包含构建完成的 `dist`，输出目录为 `dist`。
8. 回到多维表格仪表盘，在添加组件／插件入口找到自己发布的“关键节点完成汇总表”，进入配置。

飞书界面的入口名称可能随版本调整；请使用你之前成功发布柱状图插件的同一开发者中心流程。发布失败时先检查仓库公开状态、根目录结构，以及 `dist/index.html` 是否已随同提交。

> **不要覆盖原柱状图仓库或原插件。** 这是新项目，独立配置、独立发布。`package.json` 的 `private: true` 只是阻止意外发布到 npm，与 GitHub 仓库是否公开无关。

## 首次配置

1. 在“数据范围”中选择数据表、“上市时间”和“产品公司”字段。插件尝试按同名字段预选，仍需核对。
2. 在“节点字段”中点击“批量选择节点”。勾选需要的“是否完成”节点后添加。
3. 展开每个节点，确认计划完成时间、实际完成时间、是否完成这三个字段。找不到对应字段的节点会展开等待手动补选。
4. 字段选择窗口可以搜索。字段名称不规则时，点击“手动添加”并逐一映射三个字段。
5. 根据需要启用／停用节点、上下调整节点顺序，或修改三列的表头显示名称。
6. 在“数据范围”选择上市月份、产品公司。公司可通过上移／下移调整顺序。
7. 在“表格设置”修改总标题、左侧两列表头、月份排序、字号及完成率小数位。
8. 点击“添加到仪表盘”或“保存配置”。第一次创建和之后配置会使用不同按钮文字。

## 调整列宽

- 将鼠标移到表头右侧边线，出现左右调整光标后拖动。月份、公司及各节点的计划、实际、完成率列都可分别调整。
- 双击边线恢复该列默认宽度。“表格设置 → 列宽调整”支持输入具体像素值及“全部恢复默认”。
- 月份列允许 72–600px，公司列允许 100–800px，节点各列允许 64–600px。
- 月份、公司列的固定位置随列宽同步更新；节点隐藏、重新启用或调整顺序后，宽度仍跟随对应列。
- **长期保留：进入组件配置模式调整，然后点击“保存配置”。** 仪表盘查看或全屏状态也可拖动，效果保留在本次页面中；手动刷新数据不会清除本次调整，重新打开则使用已保存配置。
- 键盘操作：聚焦列边线后，左右方向键每次调整 10px，Shift 加方向键微调 1px，Home／End 调到允许的最小／最大值，Delete 恢复默认；拖动中按 Esc 取消。

## 完成率低于阈值标红

在“表格设置 → 完成率提醒”勾选“完成率低于阈值标红”，填写百分比阈值后保存配置。例如设为 80：

| 完成率 | 展示 |
| --- | --- |
| 75% 或 0% | 红字 |
| 80% 或 100% | 原色 |
| —（分母为 0） | 原色 |

阈值范围为 0–100%，作用于所有已启用节点的完成率列；计划、实际数量保持原色。比较使用未四舍五入的实际完成率，例如 79.96% 即使显示为 80% 仍低于 80% 阈值。默认关闭，兼容旧配置。

“全部”模式包含当前可读记录中出现的值，以及单选字段的现有选项；源表出现新选项时会自动加入。想只看特定月份时，切换为“勾选范围”。已选公司的每个月都会有一行，即使没有匹配记录。

## 统计口径

| 指标 | 计算规则 |
| --- | --- |
| 计划有效数量 | 计划字段排除空白、首尾空格处理后单独的 `/` 或 `／`，其他非空值每条计 1 |
| 实际有效数量 | 实际字段采用同样规则，独立计数 |
| 完成率 | 状态字段的“完成”条数 ÷（“完成”条数 + 有效“未完成”条数）；“未完成”仅在该节点计划或实际时间至少一项有效时计入 |
| 分母为 0 | 显示 `—` |
| 某月某公司没有记录 | 显示计划 `0`、实际 `0`、完成率 `—` |

- 只按源表的“上市时间”分组。计划／实际日期无需落在该上市月份。
- 时间字段中的“待定”“延期”等非空内容也计为有效；`2026/12/01` 中间的斜杠不影响计数。
- 状态去掉首尾空格后，只精确识别“完成”和“未完成”。空白及其他状态不计入完成率分母；遇到其他非空状态会在表格下方提示数量。
- 对“未完成”，若该节点的计划和实际时间都为空白或单独的 `/`、`／`，则不计入完成率分母。任一时间有效就正常计入；本次只增加对“未完成”的排除，已为“完成”的记录沿用原口径。
- 该规则按节点单独判断，不会排除整条源记录。一个节点双空不会影响这条记录的其他节点。
- 计划、实际有效数量仍各自独立计数。完成率不使用实际数量除以计划数量。
- 未开启完成率提醒时，所有数值采用统一颜色；开启后，仅低于阈值的完成率显示红字。
- 缺少上市时间或产品公司的记录不参与分组，并在表格下方提示。
- 两位年份按 2000 年之后解析，例如 `26年3月` 按 2026 年 3 月排序。分组仍使用单选项的原始名称，不自动合并不同名称的月份选项。

例如同一月份、同一公司有 3 条记录：

| 计划字段 | 实际字段 | 状态 |
| --- | --- | --- |
| 2026/12/01 | 待定 | 完成 |
| / | 2027/01/02 | 未完成 |
| 延期 | 空白 | 空白 |

结果是计划 **2**、实际 **2**、完成率 **50%**。

如果另有 3 条记录的计划、实际字段都为空，但公式状态返回“未完成”，这 3 条会被排除，完成率仍为 **50%**。如果所有状态都是这种双空“未完成”，分母为 0，显示 **—**，也不会触发低完成率标红。

## 使用和范围

- 顶部表头、左侧月份和产品公司固定；节点多时在表格内横向滚动。
- 完成率单元格悬停提示完成数、有效未完成数、分母及排除的双空未完成数量；表格下方显示排除的节点状态总数。
- “导出 CSV”导出当前选定范围和表头，UTF-8 BOM 便于 Excel 打开；导出文件每行保留月份。CSV 不包含列宽及文字颜色格式。
- 手动刷新、源表记录／字段变化通知和可见页面每 30 秒刷新会重新读取完整记录。
- 分页读取每页 200 条，按记录 ID 去重。中途失败不会显示部分或旧的统计结果。
- **本版读取当前用户有权访问的全表记录，使用插件内的月份／公司范围；不跟随仪表盘外层全局筛选或源表视图筛选。** 若需要按“是否定制”等其他字段过滤，需另行增加条件筛选功能。
- 独立浏览器页面显示连接提示，不内置演示数据。必须从飞书仪表盘打开才能读取源表。
- 不需要在代码中填写 App Secret、访问令牌或个人数据。保存的是字段 ID、选择范围和显示配置；源表仅被读取。
- 此版以汇总表为范围，不包含原柱状图的点击下钻明细功能。

## 修改代码与更新

开发需 Node.js 22.12+，精简包已含锁文件：

```powershell
npm.cmd ci
npm.cmd run dev
npm.cmd run build
```

构建会校验 `dist/index.html` 及相对资源路径。每次修改源码后，需要重新构建，并把更新后的源码和**整套新 dist** 一并提交 GitHub。推荐用 Git 完整同步；若只使用网页上传，请核对不再使用的旧资源文件，避免多次发布后堆积。

GitHub 提交完成后，还需在飞书开发者中心更新发布该新插件；仅修改仓库或保存组件配置不能保证线上代码更新。当前独立插件版本为 **v1.0.2**。

开发目录保留自动测试和浏览器验证脚本，精简上传包排除了 `tests`、`node_modules`、`output`、测试数据和本地缓存。

使用 [飞书 Bitable JS SDK](https://github.com/Lark-Base-Team/js-sdk-docs)。本项目固定 SDK 版本 `1.0.2`，使用 Base 记录读取接口和 Dashboard 配置接口。
